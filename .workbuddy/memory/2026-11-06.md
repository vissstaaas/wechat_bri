## iCloud 登录两个问题修复（OmniBridge Core）

### 背景
从 antigravity 会话（4e9fdfcc）迁移过来，该会话构建了 omnibridge-core（微信 ⇄ iCloud 数据总线）。用户反馈 iCloud 登录两个 bug。

### 根因定位
1. **登录窗口不弹**：服务端 node 进程由后台拉起，spawn 的 Playwright chromium 落在隐藏桌面（Windows 窗口站隔离），进程活着但窗口不可见。
2. **不是云上贵州**：`icloud-md@0.6.2` 库内部校验节点硬编码 `setup.icloud.com`（国际版），且 `loadSession` 会丢弃 `setupHost` 字段，导致国区账号（498158915@qq.com, dsid 10078972069, country CN）被错误打到国际版节点。

### 改动
- `src/sinks/icloud/IcloudProbe.js`：校验改走云上贵州 `setup.icloud.com.cn`，从 validate 响应提取 ckdatabasews/drivews 节点。
- `src/sinks/icloud/IcloudAuth.js`：`checkAccountAlive` 改走 IcloudProbe(.cn)；`startLogin` 改为「独立 worker + 桌面启动 + 结果文件轮询」。
- `src/sinks/icloud/icloud-login-worker.mjs`（新增）：独立进程执行 `reauthenticateFolder`/`bindNewFolderAccount`，登录抓 cookie 后写结果文件。
- `src/sinks/icloud/launch_on_desktop.ps1`：重写为正确的 Win32 `CreateProcessW` + `lpDesktop=WinSta0\default`（修正 STARTUPINFO 结构体）。
- `src/app.js`：`startLogin(LEGACY_NOTES_DIR)` 传入 notes 目录。

### 关键机制
- 登录弹窗到桌面：服务端 `spawn powershell -File launch_on_desktop.ps1 -Cmd "node worker.mjs ..."`，ps1 用 CreateProcess(lpDesktop=WinSta0\default) 把 worker 强启到交互桌面，worker 内 Playwright 弹 chromium 窗口即可见。
- 结果传递：worker 写 `~/.config/icloud-md/login-result.json`，服务端轮询（超时 5 分钟）。

## 追加：微信退出登录 + iCloud 持久登录

### 微信退出登录
- `WechatChannel.logoutChannel()`：调 SDK `logout()` 清本地凭证（`~/.openclaw/openclaw-weixin/accounts/`）+ 停 bot。
- `app.js` 新增 `POST /api/wechat/logout`。
- 前端 STEP 01 新增「退出登录」按钮（登录后显示，`logoutWechat()`）。

### iCloud 持久登录（静默续期）
- `IcloudAuth.trySilentReauth()`：421 过期时用持久 profile（`accounts/<dsid>/browser-profile`）headless 免 2FA 自动续期。
- `checkAccountAlive` 集成：`SESSION_EXPIRED` → 尝试静默续期（节流 10min、超时 30s、`silentReauthInFlight` 防并发）。
- 成功写回 session 文件；失败 fallback 到手动登录。
- **前提**：持久 profile 需有有效 device trust（用户手动登录一次建立）。当前 profile 无 device trust，静默续期实测失败（正确回退）。

### 结论
- 微信 bot token 长期有效 → 自动缓存登录是正常设计；现已有退出登录能力。
- iCloud cookie 24-48h 过期，无法永久登录；靠「device trust + 静默续期」把重登频率降到最低，仅 2FA 失效时才需手动。
