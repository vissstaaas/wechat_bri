3. **Key Findings & Diagnosis of the "没反应 / 暂无法连接 OpenClaw" Bug**
   - **Why WeChat showed "暂无法连接 OpenClaw" on the phone**:
     - In `omnibridge-core/src/channels/wechat/WechatChannel.js`, when Tencent iLink long-poll returned `status: "confirmed"`, it stored the token in memory and disk, but **it never called `start()` from `weixin-agent-sdk` to start the message receiving loop**!
     - In `weixin-agent-sdk`, a bot only actually connects to the user on WeChat when `start({ chat: async (req) => ... })` is actively running. Without `start()`, Tencent iLink considers OpenClaw offline, displaying "暂无法连接 OpenClaw" at the top of the user's phone screen!
     - **Fix Applied**: Added `startBotRuntime()` in `WechatChannel.js` which immediately invokes `start()` upon `confirmed` status (or on startup if already logged in).
   - **Why the web page didn't transition to Step 2**:
     - Frontend `public/index.html` had a guard `const justConnected = wizardGate.wechatSeen === false && connected;`. Because `wechatSeen` was initialized to `null`, `null === false` was `false`, failing to trigger `switchWizardStep(2)`.
     - **Fix Applied**: Changed to `wizardGate.wechatSeen !== true && connected` in `public/index.html`.
   - **Token Probe vs Active Long-Poll Conflict**:
     - Calling `getupdates` with an empty `get_updates_buf` and short timeout in `WechatProbe` while `start()` is actively long-polling the same bot token can cause a timeout or conflict. `src/app.js` was updated so that when `wechatChan.botInstance` is active, `tenant.wechat.connected` is directly marked `true` and `status: "ONLINE"`.
