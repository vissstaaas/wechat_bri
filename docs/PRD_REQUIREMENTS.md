**文档版本**：v1.0.0  
**定稿时间**：2026-11-06  
**安全等级**：商业保密 / 商业级架构  
**系统代号**：OmniBridge (OB.OS1)

---

## 1. 产品战略定位与愿景

### 1.1 战略定位
OmniBridge 是一个**面向多用户的跨生态智能数据集散总线与 AI 协作中枢（Omni-Channel Intelligent Data Bus & AI Bridge）**。
它立足于连接用户日常使用的即时通讯/社交生态与生产力/个人数字资产中心，扮演跨生态“连接器、分流器与智能管家”的角色。

### 1.2 阶段规划
- **Phase 1（当前核心）**：深度攻坚 **微信 (WeChat ClawBot) ⇄ Apple iCloud (备忘录 / 云盘 / 原生大图 / 相册)** 双向桥梁，实现自适应双模 AI 分流与 Siri 原生语音交互。
- **Phase 2（生态延展）**：左侧扩展 Telegram、飞书、钉钉、抖音；右侧扩展 Notion、Obsidian、私有 NAS 等个人数据资产中心。
- **Phase 3（SaaS 化商业运营）**：提供多租户云端订阅服务，面向个人高净值用户及小微团队，主打极致隐私保护与免配置开箱即用。

## 2. 目标用户画像与核心使用场景

### 2.1 目标用户画像
1. **苹果全家桶重度用户**：日常习惯使用 iPhone 备忘录、iCloud 云盘存储重要灵感、密码卡号、待办清单，但平时主要在微信中接收信息。
2. **“懒人”式信息收集者**：习惯在微信中把内容转发到文件传输助手，但缺乏主动分类整理的时间，导致信息堆积、查找困难。
3. **高隐私敏感群体**：对个人备忘录、照片极度重视隐私，严禁第三方服务常驻或持久化存储自己的隐私文件。

### 2.2 核心业务场景
- **场景 A：微信发文字/语音 ➔ 智能打标入库**：用户在微信向机器人发送“家里宽带账号 0571-88992211”，系统 <5ms 快速分流至《🔑 账号与重要速查.md》，同步至 iPhone，用户可直接对 iPhone 喊：“嘿 Siri，查一下备忘录里的宽带账号”。
- **场景 B：微信随手拍 ➔ 原生大图嵌入与云盘直传**：在微信发图片，系统零磁盘落盘（RAM-only），直接将高清原图作为原生内嵌 Attachment 嵌入《🖼️ 微信图片速记》备忘录，并同步归入 iCloud 云盘《学习照片》。
- **场景 C：微信反向调取 iCloud 数字资产**：用户在微信对机器人说“把云盘里的个人简历 PDF 发给我”，本地 AI Agent 调用工具提取云盘真实文件直接发送到微信聊天窗口。

## 3. 核心功能需求 (Functional Requirements)

### 3.1 左侧通道：微信 ClawBot 接入
- **FR-WX-01 (扫码即绑定)**：前端一键生成 iLink 二维码，用户手机微信扫码并确认即可绑定，无账密负担。
- **FR-WX-02 (真实被动探活)**：长轮询精准捕获 `-14 (session timeout)`，即刻触发掉线告警，彻底避免虚假在线。
- **FR-WX-03 (双模交互)**：
  - **模式一（信息存档模式）**：纯做快速打标归类并返回 Siri 反查提示。
  - **模式二（全能 AI 助手）**：调用 Local LLM / DeepSeek 问答并支持反查备忘录与云盘。
  - **模式三（自适应智能双模）**：根据输入语义自适应智能切换。

### 3.2 右侧通道：Apple iCloud 全生态集成
- **FR-IC-01 (备忘录原生富文本与大图直嵌)**：支持 CloudKit TopoText CRDT 拓扑合并，支持 1:1 还原 iOS 原生 Attachment 视图（`AttachmentViewType: 0` 保证大图预览，非 MacBinary 归档）。
- **FR-IC-02 (云盘文件分块直传与检索)**：通过 CloudDocs API 快速遍历目录树、流式直传课件与文档。
- **FR-IC-03 (会话 421 探活)**：每周期向 `setup.icloud.com.cn` 校验会话，遇到 `HTTP 421 / 401` 立即标记凭证过期。

### 3.3 核心路由与多租户
- **FR-MT-01 (多租户绝对隔离)**：以 `tenantId` 为隔离沙箱，每个人独享独立的微信 Session、iCloud 凭证与规则本，互不交叉。
- **FR-MT-02 (动态分类规则引擎)**：支持用户自定义新增、删除备忘录分类本与触发关键词。

## 4. 关键非功能性需求 (Non-Functional Requirements)

- **NFR-SEC-01 (零磁盘隐私保护)**：服务器内存处理流（RAM-only），严禁在磁盘上物理持久化用户个人照片、视频与备忘录正文。
- **NFR-PERF-01 (极速分流)**：本地规则分流延迟必须控制在 10ms 以内。
- **NFR-AVAIL-01 (高可用探活)**：微信与 iCloud 状态必须 100% 真实反映，严禁出现客户端与服务端状态不同步问题。
